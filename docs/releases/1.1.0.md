# Next Directory Starter 1.1.0

This release hardens the directory starter's authorization, billing, agent,
publishing, and recovery paths and completes its source-verified operator
documentation. It contains the changes since `1.0.0`.

## Security and access control

- Recheck current administrator authority inside account, catalog, plan,
  taxonomy, and theme writes so revoked sessions cannot complete stale actions.
- Normalize public sign-up responses to avoid disclosing whether an email is
  already registered.
- Derive authentication rate limits from proxy-owned client IP headers and
  document the required reverse-proxy header policy.
- Bound request bodies before JSON parsing across application, agent, payment,
  and authentication routes.

## Payments and recovery

- Preserve and reconcile Stripe, Paddle, and NOWPayments outcomes with bounded
  retries, provider cursors, purchase binding, and terminal-state ordering.
- Aggregate Paddle partial refunds, order dispute events, release expired
  hosted checkouts, and recover legacy Stripe purchases without granting the
  wrong entitlement.
- Isolate restored storage paths and require the matching billing encryption
  key with every recoverable backup.

## Agent workflows

- Add scoped staging and publication credentials, recorded browser approval,
  per-principal staging quotas, and normalized destination deduplication.
- Preserve imported categories through taxonomy changes and keep captured
  screenshots private until their listing is published.
- Allow bearer-authenticated remote MCP clients to fetch the preview returned
  by `preview_card`, while authenticated browser WebMCP continues to use the
  current account and capability checks.

## Media, SEO, and publishing

- Bound and cache generated social cards by revision, validate rendered PNG
  bytes, and fall back safely after transient source-image failures.
- Preserve suspension and article publication decisions under concurrent edits,
  retain staged taxonomy changes, and reclaim replaced private media safely.
- Reserve live redirect routes, serve correct Markdown headers for `HEAD`
  requests, and expand negative HTTP coverage around protected routes.

## Operations and documentation

- Validate SQLite URLs consistently, align CLI environment selection with the
  application, serialize migration version checks, and use Webpack for reliable
  production builds.
- Add source-linked Claude Code guidance and a complete
  [operator manual](https://github.com/eas4ai/next-directory-starter/blob/1.1.0/docs/operator-manual.md)
  covering installation, configuration, publishing, agents, billing,
  notifications, deployment, backup, restore, and upgrades.
- Pin recovery to the prior container image and document persistent storage,
  health checks, reverse-proxy limits, and non-root container operation.

## Upgrade notes

1. Back up the SQLite database, uploaded media, and matching
   `BILLING_ENCRYPTION_KEY` before replacing the current installation.
2. Install the locked dependencies with `npm ci`.
3. Run `npm run db:migrate` against the same `DATABASE_URL` used by the
   application.
4. Operational commands now use production env-file order when `NODE_ENV` is
   unset. Set `NODE_ENV=development` or `NODE_ENV=test` explicitly for jobs
   that must use those mode-specific files, and confirm their selected
   `DATABASE_URL` before running them.
5. Before routing public traffic, bind the application to loopback behind the
   reverse proxy, reject request bodies larger than 8 MiB, and overwrite both
   `X-Real-IP` and `X-Forwarded-For` with the proxy's direct client address.
   Version `1.1.0` trusts the proxy-owned `X-Real-IP` value for authentication
   rate limiting, so appending caller-supplied forwarding headers is unsafe.
6. Run `npm test` and `npm run build` before starting the upgraded service.
7. For Compose deployments, build or select the `1.1.0` image and follow the
   operator manual's backup, migration, health-check, and rollback sequence.

No manual database rewrite is required beyond the included migrations.
