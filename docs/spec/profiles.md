# Directory profiles

Prefix: PRF

[PRF-001] The starter provides versioned directory profiles independently from themes and public templates. A profile declares a stable namespaced identity and immutable version plus every field's stable key, label, help text, type, cardinality, default, constraints, write authority, visibility, display placement, search behavior, facet behavior, and sort behavior. Supported fields cover short text, Markdown text, boolean, integer, decimal, money with currency, single and multiple choice, URL, date, date/time, date range, duration, structured location, media references, and bounded repeatable structured groups. An administrator can activate a valid packaged profile, add site-owned fields in a separate namespace, inspect the impact of a profile change, and apply a compatible upgrade or an explicit mapping for an incompatible change. Activation and migration store an immutable definition and digest atomically, preserve inactive definitions and archived values, and leave the stored profile usable when its source add-on is absent.
Falsifier: A duplicate, unknown, contradictory, unsafe, unbounded, or invalid profile activates; a failed or stale activation, switch, customization, or migration partially changes the active definition or listing values; a breaking change silently coerces or deletes a value; a required-field change invalidates published records without a mapping; or removing a source add-on makes its activated database profile unreadable.
Mechanism: directory-profiles
Status: Agreed 2026-10-14

[PRF-002] Administrator and owner listing forms render accessible type-specific controls from the active profile and the server validates the complete core and profile record against the stored immutable definition. Each write enforces the field's authority and visibility, and URL, Markdown, and media-reference values retain the starter's safe-link, active-content, ownership, and public-eligibility rules. Owner profile changes use the existing private proposal, revision, submission, and moderation workflow so core and profile values publish as one approved revision. Profile lifecycle actions and permanent value purges are protected and audited, stale writes fail without a partial change, and removed fields retain archived values until a separate authorized purge.
Falsifier: A client bypasses a field constraint; unsafe active content, a dangerous URL, or an unowned media reference is stored or served; an owner changes an operator-only field; a guest or unauthorized staff account reads or changes a protected definition or value; a profile value becomes public before its matching submission is approved; moderation publishes core fields without their matching profile values; a stale write replaces newer values; a field removal erases data without an explicit purge; or a profile lifecycle action lacks its actor audit record.
Mechanism: directory-profiles
Status: Agreed 2026-10-14

[PRF-003] The public directory server-renders the active profile's configured fields, badges, groups, media, facets, and allowlisted sorts through a generic template-independent view. Text search includes only configured public searchable fields. Facets support choice, boolean, numeric, money, date, date/time, date-range, duration, and structured-location values with declared any-or-all semantics within one facet and AND semantics across facets. Date/time range bounds require explicit offsets, normalize to UTC for indexed comparison, and serialize canonically. Bounded GET parameters preserve filters and stable sorting through pagination; filtered or sorted variants remain nonindexable and identify the unfiltered directory as canonical. Queries use indexed typed values and batched reads, expose only approved eligible content, work without client JavaScript, support keyboard use, and remain readable without horizontal scrolling at 320 pixels in light and dark modes.
Falsifier: A selected facet or sort returns a record that does not match its declared semantics; a date/time range accepts an ambiguous offset-free bound, shifts an inclusive boundary, compares a non-UTC value, or serializes a different instant; pagination loses or changes the selected query; an unknown, excessive, private, staff-only, draft, rejected, suspended, or otherwise ineligible value appears in results, counts, controls, cards, details, Markdown, feeds, metadata, social cards, or structured data; a filtered URL is indexable or has the wrong canonical; one page performs a value query per listing; the discovery flow requires client JavaScript or cannot be used by keyboard; or a supported result page overflows at 320 pixels in either appearance mode.
Mechanism: directory-profiles
Status: Agreed 2026-10-15

[PRF-004] Add-on manifests may declare versioned directory-profile schema files that package validation includes in integrity, compatibility, identity, path-safety, and ownership checks without opening the operator database. Explicit sample seeding names a profile version, validates the complete typed batch before one idempotent transaction, and writes no partial records. Agent imports may stage incomplete profile data but cannot publish until required fields validate. Add-on removal does not delete activated definitions or values. Documented migration, backup, isolated restore, and upgrade workflows preserve profile definitions, custom fields, current and archived values, and migration history.
Falsifier: Installing or removing a profile-bearing add-on changes operator database state; an invalid, incompatible, duplicate, corrupt, unsafe, or colliding profile package changes the workspace; explicit seeding writes a partial or wrongly typed batch or duplicates records on retry; an incomplete agent import becomes public; removing the package deletes or strands activated data; or a documented backup, restore, migration, or upgrade loses a definition, field, current value, archived value, or migration record.
Mechanism: directory-profiles
Status: Agreed 2026-10-14
